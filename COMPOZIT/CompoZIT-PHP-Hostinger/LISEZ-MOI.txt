  CompoZ'IT - version PHP pour hebergement mutualise Hostinger
=========================================================================

Contenu du pack
---------------
  site/                     -> LE SITE. Son contenu est a deposer dans
                               public_html (pas le dossier "site" lui-meme).
  base_de_donnees/
      compozit.sql           -> export de la base (structure + donnees),
                                a importer via phpMyAdmin si tu repars d'une
                                base vide.
  LISEZ-MOI.txt             -> ce fichier.


Pourquoi une version PHP et pas la version Rust ?
-------------------------------------------------
Hostinger mutualise n'execute que du PHP "a la demande" : pas de processus
permanent, pas de port ouvert, pas de Docker. La version Rust ne peut donc
pas y tourner. Cette version PHP est l'equivalent fonctionnel : memes tables,
memes donnees, meme compte utilisateur.


Etape 1 - Preparer la base MySQL
--------------------------------
1. hPanel -> Bases de donnees -> MySQL Databases
2. Note les identifiants affiches :

      Hote         : localhost
      Base         : uxxxxxxx_compozit
      Utilisateur  : uxxxxxxx_mr-j
      Mot de passe : celui defini dans hPanel

   Ils sont deja renseignes dans site/config.local.php.
   Si tu changes le mot de passe, mets-le a jour dans ce fichier.

3. Deux cas :
   a) La base contient deja tes donnees (celle utilisee par l'application de
      bureau) -> ne touche a rien, passe a l'etape 2.
      L'application ajoute au besoin les tables/colonnes manquantes toute seule.
   b) Tu repars d'une base vide -> phpMyAdmin -> Importer ->
      base_de_donnees/compozit.sql


Etape 2 - Deposer le site
-------------------------
1. hPanel -> Gestionnaire de fichiers (ou FTP avec FileZilla)
2. Ouvre le dossier public_html de ton domaine
3. Envoie TOUT LE CONTENU du dossier site/ (selectionne les fichiers, pas le
   dossier "site" lui-meme), de sorte que index.php se retrouve directement
   dans public_html/

   ATTENTION : le fichier .htaccess doit aussi etre envoye, a cote de
   index.php. Les clients FTP masquent les fichiers commencant par un point :
   dans FileZilla, active "Serveur -> Forcer l'affichage des fichiers caches".


Etape 3 - Choisir la version de PHP
-----------------------------------
hPanel -> Avance -> Configuration PHP du domaine
      Version PHP    : 8.1 ou 8.2   (8.0 minimum : le code utilise
                                     str_starts_with, apparu en PHP 8.0)
      upload_max_filesize : 20M minimum
      post_max_size       : 24M minimum

Puis redemarre l'application PHP (bouton dedie dans hPanel) pour appliquer.


Etape 4 - Activer le HTTPS
--------------------------
hPanel -> Securite -> SSL -> installer le certificat gratuit.
La redirection http -> https est deja prete dans le .htaccess du site.


Etape 5 - Se connecter
----------------------
Ouvre https://ton-domaine.com

Connecte-toi avec LE MEME email / mot de passe que dans l'application de
bureau : c'est la meme table "users", et les composants / projets / casiers
sont rattaches a ce compte. Un nouveau compte ne verrait aucune donnee.

Si tu as importe compozit.sql dans une base vide, le compte de demonstration
est :   admin@compozit.fr   /   admin123
Change ce mot de passe tout de suite dans Profil.


Ce qui a ete adapte pour l'hebergement mutualise
------------------------------------------------
* config.php
  La creation automatique de la base (CREATE DATABASE) ne bloque plus le
  demarrage. Sur un hebergement mutualise, l'utilisateur MySQL n'a pas ce
  droit : l'echec est ignore et l'application utilise la base deja creee
  dans hPanel. Sur XAMPP le comportement reste identique.

* Dossier des projets : "projets" en minuscules
  Les serveurs Linux sont sensibles a la casse. Le dossier s'appelait
  "Projets" sous Windows ; il a ete renomme "projets" et les chemins stockes
  en base ont ete harmonises, sinon les photos et fichiers de projets
  deviendraient introuvables apres la mise en ligne.

* .htaccess (racine du site)
  - redirection http -> https
  - blocage du telechargement des fichiers sensibles
    (config.local.php, *.sql, *.bak, *.log...)
  - blocage du dossier tmp/ (sessions PHP + jetons d'API)
  - listing des dossiers desactive, quelques en-tetes de securite

* config.local.php
  Identifiants Hostinger et cles d'API deja renseignes.
  Ce fichier contient des secrets : il ne doit jamais se retrouver
  telechargeable. C'est le role du .htaccess ci-dessus.

* Retires du pack (outils Windows sans objet en ligne) :
  start_server.bat, start_server.template.bat, setup_auto_images.bat,
  setup_auto_images.template.bat, config.local.php.bak


Sauvegardes
-----------
Depuis l'application : Parametres -> Import/Export.

  Export : telecharge un fichier compozit_AAAA-MM-JJ_HH-MM-SS.sql
           (structure + donnees), a conserver en lieu sur.

  Import : restaure un fichier .sql par upload (20 Mo maximum).
           Les tables existantes sont recreees a partir du fichier : la
           restauration est complete, pas un ajout.

  Au-dela de 20 Mo, ou pour une sauvegarde manuelle :
  hPanel -> Bases de donnees -> phpMyAdmin -> onglet Exporter.


Base de marquage CMS (codes imprimes sur les boitiers)
-----------------------------------------------------
Les boitiers CMS portent un code court (2 a 4 caracteres, ex. 65V, J1, 2A)
au lieu de la reference complete. La page "Marquage" permet de retrouver la
reference a partir de ce code, et le formulaire de composant propose le meme
champ avec autocompletion.

Le fichier base_de_donnees/marking_codes.sql (environ 60 Mo, fourni a part)
n'est pas envoye avec le reste du site : trop volumineux, et il est de toute
facon interdit au telechargement par le .htaccess.

  1. Envoie le fichier dans le dossier base_de_donnees/ du site PAR FTP
     (FileZilla), pas par le gestionnaire de fichiers du navigateur.
  2. Dans l'application : Parametres -> Base de marquage CMS -> "Installer la
     base de marquage". L'installation se fait par lots et affiche sa
     progression (quelques dizaines de secondes).
  3. Une fois terminee, clique sur "Supprimer le fichier .sql du serveur" :
     la table est installee, le fichier de 60 Mo n'est plus utile.

La table creee s'appelle marking_codes. Elle est independante de ton
inventaire : sa reinstallation ne touche ni les composants, ni les projets.


Depannage
---------
"Erreur de connexion a la base de donnees"
    -> Verifie DB_HOST / DB_NAME / DB_USER / DB_PASSWORD dans
       site/config.local.php. Chez Hostinger, l'hote est "localhost".
       Le nom de base et l'utilisateur commencent par u317855591_.

"Erreur d'initialisation de la base de donnees"
    -> La base n'existe pas encore : cree-la dans hPanel (etape 1).

Page blanche
    -> hPanel -> Avance -> Journaux d'erreurs, ou active temporairement
       l'affichage des erreurs dans la configuration PHP.

Erreur 500 des la premiere page
    -> Le .htaccess n'a pas ete envoye correctement (fichier cache ignore par
       le client FTP, ou mode de transfert errone). Renvoie-le en mode texte.

L'upload d'une image ou d'un datasheet echoue
    -> Le dossier img/ (et datasheets/) n'est pas inscriptible. Passe-le en
       755 depuis le gestionnaire de fichiers.

Le projet s'affiche mais ses photos / fichiers sont introuvables
    -> Verifie que le dossier s'appelle bien "projets" en minuscules a la
       racine du site, en minuscules exactement.
